# EDD-1356 v2 — endurecimento do script de merge

**Branch:** `EDD-1356` (base: EDD-1359 com o fork em 0.63.x)  
**Script:** `bin/merge-upstream-preserve-sp.sh`  
**Origem:** lições da PoC EDD-1355 (60 → 61 → 62 → 63) e do primeiro deploy da 63.  
**Status:** implementada; revisitar após a EDD-1362.

---

## Por que a v2

Na PoC, o MVP do script deixou dois tipos de problema que só apareceram tarde:

1. **Arquivos com conteúdo de versões anteriores** (0.60/0.61/0.62) no meio do código da 63. Causas:
   - no `restore`, conflito em arquivo não-SP ficava com a versão do fork;
   - qualquer imagem (`*.png` etc.) era restaurada do fork, inclusive docs e baselines `.loki`;
   - o filtro "arquivo tocado por commit EDD-*" tratava como SP arquivos que só foram tocados por commits de upgrade.
2. **Dev passando e build de produção quebrando.** O dev (`--hot` + rspack serve) não compila drivers nem namespaces não carregados e trata import quebrado como aviso. O `bin/build.sh` quebrou com:
   - `starburst.clj` da 0.62 usando `driver/describe-table-fks`, removido no core 63;
   - imports do frontend EE apontando para caminhos da 0.62 (`ESModulesLinkingError`).

## O que mudou

### Novos comandos

| Comando | O que faz |
| ------- | --------- |
| `scan` | Compara o projeto com `UPSTREAM_REF` e classifica tudo que não é SP protegido. Gera `.merge-sp/scan-report.md` |
| `scan --apply` | Restaura do upstream os **stale** e **missing** e apaga os **órfãos** (`APPLY_HYBRID=1` inclui os híbridos) |
| `build-check` | Carrega todos os namespaces (src, EE, drivers) com `-M:drivers:ee`, compila o static-viz e o bundle FE de produção (EE). Passos isolados com `BUILD_CHECK_STEPS` |

Categorias do `scan`:

| Categoria | Critério | Ação |
| --------- | -------- | ---- |
| stale | conteúdo igual ao pré-merge (`PRE_MERGE_REF`) ou a qualquer tag `saopaulo-pre-*` | restaurar do upstream |
| missing | existe no upstream, falta no fork | restaurar do upstream |
| orphan | existe no fork, apagado no upstream | apagar |
| hybrid | diferente do upstream e de todos os snapshots | revisar: se for SP, adicionar às listas; senão restaurar |

O `scan` também avisa quando `package.json`, `bun.lock` e `patches/` diferem do upstream (os três devem andar juntos).

### Comandos existentes

- **`restore`:**
  - conflito em arquivo fora das listas → versão do **upstream** (`UNMERGED_POLICY=sp` volta ao comportamento do MVP); o resultado fica em `.merge-sp/unmerged-resolved.txt`;
  - imagens/fontes só são restauradas do fork dentro de `resources/frontend_client/`.
- **`verify`:** passou a rodar o `scan` e falha se sobrar stale, missing ou órfão (`VERIFY_SCAN=0` desliga).

### Nova lista `lists/sp-extra.txt`

Protege do `scan` o que é SP mas não está nos 3 buckets. Aceita glob. Não entra no restore automático.

- Infra do fork: `bin/docker/Dockerfile`, `bin/build-and-push-docker.sh`, o próprio script, `mise.toml`, `.husky/pre-commit`, `docs/internal/*`.
- Marca: fontes Rawline, `app/assets/img/*`, `app/img/*`.
- Tradução: `locales/metabase.po`.
- Código SP que só constava no manifesto (login, legenda, eixos, séries, botão, DashCard, LDAP).
- `HomeXrayCard.tsx` (não estava em lista nenhuma).
- Endurecimentos pós-63 do crash ao salvar question.

**Regra:** SP protegido = `restore-ours` + `dual-changed` + `behavior-manual` + `sp-extra`. Nada mais é SP. Customização nova → adicionar a uma dessas listas no mesmo PR.

## Fluxo atualizado

```bash
bash bin/merge-upstream-preserve-sp.sh snapshot
bash bin/merge-upstream-preserve-sp.sh merge
bash bin/merge-upstream-preserve-sp.sh restore
bash bin/merge-upstream-preserve-sp.sh report
# resolver dual-changed + behavior-manual à mão
bash bin/merge-upstream-preserve-sp.sh scan          # ler .merge-sp/scan-report.md
bash bin/merge-upstream-preserve-sp.sh scan --apply  # stale/missing/orphan
bash bin/merge-upstream-preserve-sp.sh verify
bash bin/merge-upstream-preserve-sp.sh build-check   # BE/FE dev parados (WSL ~8 GiB)
# smoke canônico: checklist-smoke-test.md
```

Use `bash …` se o WSL não respeitar o bit executável. Detalhes: [runbook-atualizacao.md](./runbook-atualizacao.md).

## Limpeza aplicada nesta branch

Com o `scan` da v2:

- 217 arquivos de `docs/`, locales de outros idiomas, `release/` e `.loki/` restaurados do upstream 63 (3 deles eram híbridos só de docs, sem conteúdo SP);
- 3 docs órfãos removidos;
- **mantidos como estão** (decisão do time): workflows de `.github/` e `.gitignore`. Eles continuam aparecendo no `scan` (21 stale, 9 órfãos, 2 híbridos).

Nenhum arquivo de código mudou na limpeza.
